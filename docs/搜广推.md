

# 搜广推是指什么？

**搜广推**是互联网行业里对三个业务方向的统称：

> **搜 = 搜索（Search）**
>  **广 = 广告（Advertising）**
>  **推 = 推荐（Recommendation）**

三者表面业务不同，但底层技术高度重合，核心都可以抽象成：

**从海量候选内容中，在很短时间内，为当前用户/请求找到最合适的一批结果，并进行排序。**

### 搜：搜索

用户有明确意图，例如搜索“机械键盘”。

典型链路：

```
用户 Query
   ↓
Query 理解
   ↓
召回 Recall
   ↓
粗排
   ↓
精排 Ranking
   ↓
重排
   ↓
搜索结果
```

重点技术包括信息检索、倒排索引、Embedding/向量检索、Query 理解、相关性模型、Learning to Rank 等。

### 广：广告

它和搜索/推荐最大的不同之一，是除了考虑“用户喜欢什么”，还涉及**商业约束和交易机制**：

```
广告请求
   ↓
用户/上下文特征
   ↓
广告候选召回
   ↓
过滤
   ↓
CTR/CVR/价值预估
   ↓
排序
   ↓
出价 / 竞价
   ↓
广告展示
   ↓
曝光 → 点击 → 转化
```

典型技术包括：

```
广告召回
CTR 预估
CVR 预估
CTCVR 预估
OCPX
出价策略
预算控制
流量分配
竞价机制
归因
反作弊
用户画像
特征工程
实时特征
```

### 推：推荐

用户通常没有输入明确 Query，系统主动预测他可能喜欢什么。比如短视频 Feed、新闻流、电商猜你喜欢。

```
用户
 ↓
用户画像 / 实时行为
 ↓
多路召回
 ├─ 协同过滤
 ├─ Embedding
 ├─ 热门召回
 ├─ 兴趣召回
 └─ 实时行为召回
 ↓
粗排
 ↓
精排
 ↓
重排
 ↓
Feed
```

核心问题是：

> **这个用户下一刻最可能对什么内容感兴趣？**

# 为什么放在一起叫“搜广推”

因为它们的核心技术链路越来越像：

```
                    搜广推
                      │
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
       搜索           广告           推荐
        │             │             │
        └─────────────┼─────────────┘
                      ↓
                   用户理解
                      ↓
                   特征系统
                      ↓
                   候选召回
                      ↓
                   粗排模型
                      ↓
                   精排模型
                      ↓
                   重排策略
                      ↓
                在线 Serving
                      ↓
             曝光 / 点击 / 转化
                      ↓
                日志 + 大数据
                      ↓
                 模型训练
                      ↓
                 更新模型
```

因此它们共享大量技术：**召回、排序、CTR/CVR 预估、Embedding、特征工程、实时计算、大数据、机器学习、在线推理、高并发 Serving、A/B Test**。

# 广告系统研究明白了，是不是研究搜索和推荐更容易一些?

**是的，但要分“系统工程”和“算法”两个层面看。**

如果你把程序化广告真正研究透，尤其是把**广告引擎 + 大数据 + 算法链路**都打通，再研究搜索、推荐会明显容易，因为三者大量基础设施和方法论是共通的。

可以粗略理解成：

```
                 搜广推共同底座
                      │
        ┌─────────────┼─────────────┐
        │             │             │
      搜索            广告           推荐
        │             │             │
      Query          竞价          用户兴趣
      相关性          出价          内容理解
        │             │             │
        └────── 召回 → 排序 → 重排 ──────┘
                      │
              CTR / CVR 等预估
                      │
             特征 / Embedding
                      │
          实时计算 + 离线计算
                      │
          数据仓库 / 特征平台
                      │
              在线 Serving
```

从**广告 → 推荐**，迁移尤其顺畅。广告里的用户画像、特征工程、多路召回、CTR/CVR 预估、粗排/精排、实时特征、曝光点击日志、A/B 实验等，在推荐系统里大量存在。主要需要补的是推荐特有的**协同过滤、内容理解、兴趣建模、多目标排序、多样性/新颖性、Feed 策略**等。

从**广告 → 搜索**也能迁移很多，但需要补一个比较大的领域——**信息检索（IR）**。例如：

```
分词 / Query 理解
        ↓
倒排索引
        ↓
BM25 等传统相关性
        ↓
Query-Document Matching
        ↓
向量检索 / ANN
        ↓
语义召回
        ↓
Learning to Rank
        ↓
搜索重排
```

所以“广告研究明白后，搜索推荐是不是就简单了”，更准确的说法是：

> **不是搜索推荐本身变简单，而是你已经掌握了搜广推大约一半以上的共同基础设施和思维框架。**

而且广告其实是一个很适合作为入口的方向，因为它额外包含不少搜索/推荐不一定有的复杂问题：**RTB、竞价机制、出价、预算控制、成本控制、归因、计费、流量交易、OCPX、反作弊、商业约束**。

如果你最终把广告做到这种程度：

```
业务
ADX / SSP / DSP / RTA / OCPX
          ↓
工程
高并发广告引擎 / 实时 Serving
          ↓
数据
Kafka / Flink / Lakehouse / OLAP
          ↓
算法
召回 / CTR / CVR / 排序 / 出价
          ↓
平台
特征平台 / 模型训练 / A/B Test / 监控
```

再去研究推荐，你会发现很多东西是“**换了业务目标继续用**”；再去研究搜索，则主要集中补 **IR + Query/Document 相关性体系**。

因此，如果你的长期目标是从**程序化广告专家进一步扩展成搜广推系统专家**，我反而不建议现在同时平均学习三个方向。可以先把**广告纵向打穿**，然后按：

**广告 → 推荐 → 搜索**

扩展。这样比同时开三条线效率高很多，而且最终形成的是非常完整的：

> **高并发系统 + 大数据 + 搜广推算法 + 商业化系统**

这条技术能力组合。
