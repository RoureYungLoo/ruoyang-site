# 快速入门

## 经典瀑布流程的核心阶段

### 1. 可行性研究与计划

**目标：** 判断项目是否值得做、能不能做。

主要活动：

- 分析业务目标、成本和收益
- 评估技术可行性、经济可行性、法律可行性、运行可行性
- 制定初步项目计划、进度、资源估算

产出物：可行性研究报告、项目计划书。

### 2. 需求分析

**目标：** 明确系统“做什么”，而不是“怎么做”。

主要活动：

- 与用户、干系人沟通，收集需求
- 区分功能需求、性能需求、界面需求、安全需求等
- 建立需求模型，如用例图、数据流图、状态图
- 评审需求，消除歧义和冲突

产出物：需求规格说明书（SRS）、需求跟踪矩阵。

### 3. 概要设计

**目标：** 确定系统整体结构和技术方案。

主要活动：

- 划分系统模块/子系统
- 设计模块之间的接口
- 确定数据库结构、技术架构、部署架构
- 选择关键技术栈和中间件

产出物：概要设计说明书、架构图、数据库设计文档。

### 4. 详细设计

**目标：** 明确每个模块内部的具体实现逻辑。

主要活动：

- 设计每个模块的算法、数据结构
- 细化接口参数、异常处理
- 设计界面原型、报表格式
- 编写伪代码或流程图

产出物：详细设计说明书、模块设计文档、数据库表结构详细定义。

### 5. 编码与单元测试

**目标：** 将设计转化为可运行的程序，并验证单个模块正确性。

主要活动：

- 按设计文档编写代码
- 遵循编码规范和版本管理
- 进行代码走查/审查
- 对每个模块做单元测试，修复缺陷

产出物：源代码、单元测试用例、单元测试报告。

### 6. 测试

**目标：** 验证整个系统是否满足需求，发现并修复缺陷。

主要活动：

- **集成测试：** 验证模块之间的接口和协同工作
- **系统测试：** 在真实或模拟环境中测试功能、性能、安全、兼容性
- **验收测试：** 由用户/客户确认系统是否满足业务需求

产出物：测试计划、测试用例、缺陷记录、测试报告。

### 7. 部署与交付

**目标：** 将系统安装到生产环境，正式交付使用。

主要活动：

- 部署应用程序、配置服务器和数据库
- 数据迁移、初始化
- 用户培训、编写操作手册
- 上线试运行、正式切换

产出物：部署文档、用户手册、验收报告。

### 8. 运行与维护

**目标：** 保证系统持续稳定运行，并根据需求变化进行修改。

主要活动：

- 修正性维护：修复线上缺陷
- 适应性维护：适应软硬件环境变化
- 完善性维护：增加新功能、优化性能
- 预防性维护：提前发现潜在问题

产出物：维护记录、变更请求、版本发布说明。
